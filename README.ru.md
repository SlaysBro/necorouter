# necorouter

Программный маршрутизатор для Linux с интерфейсом командной строки в стиле коммерческих маршрутизаторов.
Это один бинарный файл на Go, который управляет известными демонами Linux (FRR, dnsmasq, chrony, nftables, strongSwan)
по одной конфигурации.

> **Статус:** версия 0.21.1, учебный и лабораторный проект. Охватывает команды, которые нужны в упражнениях и экзаменах
> по сетевому администрированию. Это не продуктивный маршрутизатор, и не каждая функция проверена на реальном железе.

## О проекте

necorouter создан как учебный проект: чтобы понять, как устроен маршрутизатор, построив его самому. Это не копия
чьего-либо продукта. Синтаксис команд взят по образцу коммерческих CLI маршрутизаторов, чтобы команды были знакомы
тем, кто с ними работал.

Код написан с помощью **Claude**, ИИ-ассистента от Anthropic: его использовали для проектирования, генерации кода,
тестов и проверки. Также **OpenAI Codex** использовался для поиска и исправления ошибок, доработки тестов и проверки изменений.
Сам роутер написан на **Go** и использует только стандартную библиотеку.

## Возможности

- Адреса интерфейсов, статические маршруты, DNS, порты и VLAN (`port teN`, сервис-инстансы, `dot1q`), GRE-туннели.
- NAT: динамический NAT с overload и статический destination NAT с необязательным hairpin.
- DHCP-сервер (dnsmasq), NTP-клиент (chrony), OSPF (FRR).
- IPsec: IKEv1 и IKEv2 с предварительными ключами, GRE over IPsec (strongSwan).
- Карты маршрутов, префиксные списки и списки политик маршрутизации.
- Списки доступа (`filter-map ipv4`), профили безопасности.
- Пользователи с ролями, входа — через учётные записи Linux, пароли хранятся только хешами.
- Конфигурация: `write` сохраняет стартовую конфигурацию, автоматические резервные копии, именованные файлы конфигурации,
  сравнение и историю.
- Собственный журнал событий и аудит действий пользователей, не зависящие от journald и syslog.
- Удобства CLI: подсказки `?`, дополнение по Tab, история команд, постраничный вывод, `show ... | include/exclude/grep`.

## Как это работает

- `necorouter daemon` — фоновая служба. Она хранит текущую конфигурацию и применяет её к системе.
- `necorouter` (CLI) подключается к демону через локальный Unix-сокет. Каждый вход открывает отдельную сессию.
- Каждая функция системы реализована отдельным стандартным демоном или утилитой. Они запускаются только тогда,
  когда конфигурация в них нуждается, и останавливаются, когда настройка удалена:

| Функция | Компонент |
|---|---|
| Вход и SSH | учётные записи Linux (PAM), OpenSSH |
| NAT, filter-map, профили безопасности | nftables |
| DHCP и DNS | dnsmasq |
| OSPF | FRR (zebra, ospfd) |
| NTP | chrony |
| IPsec | strongSwan (charon, swanctl) |
| ping и traceroute | iputils, traceroute |

Пакеты для каждого дистрибутива перечислены в [`packaging/DEPENDENCIES`](packaging/DEPENDENCIES).

## Поддерживаемые системы

- **Дистрибутивы:** Debian и Ubuntu (также Astra Linux, Raspberry Pi OS); CentOS, RHEL, Rocky, AlmaLinux,
  Fedora, RedOS, Oracle Linux, Amazon Linux, openEuler; Alpine Linux.
- **Системы инициализации:** systemd и OpenRC.
- **Архитектуры:** amd64 и arm64 (статические бинарники, `CGO_ENABLED=0`).
- **Для сборки:** Go 1.24 или новее.

Установщик определяет семейство дистрибутива по `/etc/os-release`. Не все дистрибутивы проверены на реальном
железе: установщик и скрипты служб проверялись в эмулированных окружениях, в том числе на Alpine.

## Установка

1. **Получите установщик.** Клонируйте репозиторий или скачайте архив исходников со страницы
   [Releases](https://github.com/SlaysBro/necorouter/releases):

       git clone https://github.com/SlaysBro/necorouter.git
       cd necorouter

2. **Установите** от root. По умолчанию установщик скачивает последний стабильный релиз с GitHub,
   проверяет его по `SHA256SUMS`, пытается установить необходимые системные пакеты, копирует бинарник в `/usr/local/bin`,
   создаёт ссылку `/usr/bin/necorouter` и включает и запускает службу:

       sudo sh packaging/install.sh

   Репозиторий GitHub задан в [`packaging/source.conf`](packaging/source.conf).

   Для загрузки используется имеющийся `curl`, `wget`, `wget` из BusyBox или Python 3. Если загрузчиков нет,
   установщик попробует поставить `curl` через пакетный менеджер системы (кроме режима `--no-deps`). Файл контрольных
   сумм скачивается из того же релиза: он выявляет повреждение загрузки, но не является отдельной подписью релиза.
   Установщик не обновляет всю ОС, но пакетный менеджер может обновить пакеты, необходимые роутеру.

   Параметры установщика:

| Параметр | Значение |
|---|---|
| *(нет)* | скачать последний стабильный релиз (pre-release пропускаются) |
| `--version TAG` | установить конкретный релиз, например `--version 0.21` |
| `--pre` | установить самый новый релиз, включая pre-release (беты) |
| `--build` | собрать из исходников рядом с установщиком вместо загрузки (нужен Go 1.24+) |
| `--local` | использовать уже имеющийся бинарник: рядом с установщиком, в `dist/` или в `PATH` |
| `--bin PATH` | установить этот файл бинарника (или каталог с ним) |
| `--no-enable` | только установка, без включения и запуска службы |
| `--no-deps` | не устанавливать системные пакеты |
| `--uninstall [--purge]` | удалить роутер; `--purge` также удаляет учётные записи роутера, конфигурации, историю и журналы |

   Повторный запуск установщика ставит последний релиз поверх текущего; конфигурация сохраняется.

   Чтобы собрать самому: `make` (создаст `dist/necorouter-x86_64` и `dist/necorouter-aarch64`, нужен Go 1.24+),
   затем `sudo sh packaging/install.sh --local`.

3. **Проверьте**, что служба работает:

       necorouter version
       systemctl status necorouter        # systemd
       rc-service necorouter status       # OpenRC / Alpine

4. **Войдите** по SSH или на консоли под учётной записью Linux. Встроенная учётная запись — `admin` с паролем
   `admin`. После входа роутер предупреждает о пароле по умолчанию; смените его сразу:

       configure terminal
       username admin
       password НОВЫЙ_ПАРОЛЬ
       end

5. **Сопоставьте порты с сетевыми картами.** Порты `te0`, `te1` и т. д. назначаются физическим интерфейсам через
   `/etc/necorouter/ports.map`. Новые карты добавляются автоматически и сопоставляются по MAC-адресу.

### Удаление

    sudo sh packaging/install.sh --uninstall           # сохранить конфигурации
    sudo sh packaging/install.sh --uninstall --purge   # удалить всё, включая учётные записи роутера

## Обновление

В привилегированном режиме:

    update check            текущая версия, последний стабильный релиз и последний pre-release
    update list [N]         последние N релизов (по умолчанию 10)
    update                  установить последний стабильный релиз (с подтверждением)
    update pre              установить самый новый pre-release
    update to TAG           установить конкретный релиз, например `update to v0.21`; более старые релизы — понижение версии

Обновление идёт в фоне: роутер перезапускается, сессии завершаются. Ход обновления записывается в
`/var/log/necorouter/update.log`. Релизы проверяются по `SHA256SUMS`; суммы взяты из того же релиза, поэтому они
защищают от повреждённой загрузки, но не от подменённого релиза. Эти команды обновляют только necorouter, но не ОС.

## Быстрый старт: пример конфигурации

Пример подключает один интерфейс к LAN, добавляет пользователя и раздаёт DHCP в этой сети.
Предполагается, что физический интерфейс для порта `te0` указан в `ports.map`.

    hostname router1
    ip domain-name lab.local
    !
    interface lan
     ip address 192.168.10.1/24
    !
    port te0
     service-instance te0/lan
      encapsulation untagged
      connect ip interface lan
    !
    end

Как применить:

1. Войдите, перейдите в привилегированный режим командой `enable`, затем `configure terminal`.
2. Вставьте строки выше или введите их по одной.
3. Проверьте результат командой `show running-config`.
4. Сохраните командой `write`. Без `write` конфигурация пропадёт при перезапуске демона.

Полезные команды: `?` показывает, что можно ввести дальше, `show running-config` — действующую конфигурацию,
`write` — сохранение, `exit` — выход из текущего режима. Полный справочник команд — в
[`docs/index.html`](docs/index.html).

## Ограничения

- Статический IPsec (ключи `manual`, `show crypto sa`) не реализован; реализован только IPsec с IKE.
- BGP не реализован. Карты маршрутов поддерживают перераспределение в OSPF, но не атрибуты BGP.
- Удалённый syslog и `aaa` с TACACS+ или RADIUS не реализованы.
- Часть команд следует дизайну коммерческих маршрутизаторов, а не официальной спецификации. Перед тем как полагаться
  на необычную команду, проверьте её поведение.
- Работа OSPF на FRR, DHCP, NAT и GRE на реальном железе и на каждом поддерживаемом дистрибутиве не проверена.

## Сборка и тесты

    make                # статические бинарники для amd64 и arm64
    make host           # бинарник для этой машины
    make test           # go vet, юнит-тесты и сквозные скрипты

`make test` требует root и `unshare`: сквозные скрипты создают сетевые пространства имён и виртуальные интерфейсы.
Только юнит-тесты: `go test ./...`.

## Версии

Версии имеют вид `0.NN` для релизов с новыми возможностями и `0.NN.P` для мелких изменений и исправлений поверх `0.NN`
(например, `0.22`, затем `0.22.1`). Релиз с новыми возможностями увеличивает `NN` на единицу, исправление — `P`.
Предварительные версии помечаются как `0.NN-beta.N`. Первый публичный релиз — `0.21`.
Версия 1.0 пока не запланирована.
