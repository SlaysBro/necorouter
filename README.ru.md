# necorouter

Программный маршрутизатор для Linux с интерфейсом командной строки в стиле коммерческих маршрутизаторов.
Один бинарник на Go управляет известными демонами Linux (FRR, dnsmasq, chrony, nftables, strongSwan) из одной конфигурации.

## О проекте

necorouter создан как учебный проект: чтобы понять, как работают маршрутизаторы, сделав один самому.
Это не копия ПО какого-либо производителя. Синтаксис команд повторяет CLI коммерческих маршрутизаторов,
чтобы команды были знакомы тем, кто с такими устройствами работал.

> **Статус:** версия 0.23-beta.1, учебный и лабораторный проект. Он покрывает команды, которые используются
> в упражнениях и экзаменах по сетевому администрированию. Это не промышленный маршрутизатор, и не все функции
> проверены на реальном оборудовании.

Код написан с помощью **Claude**, ИИ-ассистента от Anthropic: он использовался для проектирования, генерации кода,
тестов и ревью. **OpenAI Codex** использовался для отладки, улучшения тестов и проверки изменений.
Сам маршрутизатор написан на **Go** и использует только стандартную библиотеку.

Основные функции: адреса интерфейсов, статические маршруты, DNS, порты и VLAN, GRE-туннели, NAT, ограничение
полосы (CAKE), DHCP-сервер, NTP-клиент, OSPF, IPsec (IKEv1 и IKEv2), route-map, списки доступа, профили безопасности,
пользователи с ролями, файлы конфигурации с историей и журнал действий пользователей.

## Установка

### Требования и поддерживаемые системы

- **Дистрибутивы:** Debian и Ubuntu (также Astra Linux, Raspberry Pi OS); CentOS, RHEL, Rocky, AlmaLinux,
  Fedora, RedOS, Oracle Linux, Amazon Linux, openEuler; Alpine Linux.
- **Системы инициализации:** systemd и OpenRC.
- **Архитектуры:** amd64 и arm64 (статические бинарники, `CGO_ENABLED=0`).
- **Минимальное железо:** 1 ядро процессора и 2 потока.
- **Для сборки:** Go 1.24 или новее (только если собираете из исходников).

Установщик определяет семейство дистрибутива по `/etc/os-release`. Не на каждом дистрибутиве проверена работа
на реальном железе: установщик и скрипты служб проверены в эмулируемых окружениях, включая Alpine.
Пакеты для каждого дистрибутива перечислены в [`packaging/DEPENDENCIES`](packaging/DEPENDENCIES).

### Установка

1. Получите установщик. Клонируйте репозиторий или скачайте архив исходников со страницы
   [Releases](https://github.com/SlaysBro/necorouter/releases):

       git clone https://github.com/SlaysBro/necorouter.git
       cd necorouter

2. Установите от root. По умолчанию установщик скачивает последний стабильный релиз с GitHub, проверяет его по
   `SHA256SUMS`, по возможности ставит нужные системные пакеты, копирует бинарник в `/usr/local/bin`,
   создаёт ссылку `/usr/bin/necorouter`, включает и запускает службу:

       sudo sh packaging/install.sh

   Репозиторий GitHub задан в [`packaging/source.conf`](packaging/source.conf).

   Для загрузки используется `curl`, `wget`, BusyBox `wget` или Python 3. Если ничего из этого нет, установщик
   пытается поставить `curl` через менеджер пакетов (если не задан `--no-deps`). Файл контрольных сумм берётся из
   того же релиза: он выявляет повреждения при передаче, но не является отдельной подписью релиза.
   Установщик не обновляет всю операционную систему; менеджер пакетов может обновить пакеты, нужные маршрутизатору.

   Параметры установщика:

   | Параметр | Значение |
   |---|---|
   | *(нет)* | скачать последний стабильный релиз (предварительные версии пропускаются) |
   | `--version TAG` | установить конкретный релиз, например `--version 0.21` |
   | `--pre` | установить новейший релиз, включая предварительные версии (беты) |
   | `--build` | собрать из исходников рядом с установщиком (нужен Go 1.24+) |
   | `--local` | использовать уже имеющийся бинарник: рядом с установщиком, в `dist/` или в `PATH` |
   | `--bin PATH` | установить указанный бинарник (или каталог, в котором он лежит) |
   | `--no-enable` | только установить, не включать и не запускать службу |
   | `--no-deps` | не устанавливать системные пакеты |
   | `--uninstall [--purge]` | удалить маршрутизатор; `--purge` дополнительно удаляет учётные записи, конфигурации, историю и журналы |

   Повторный запуск установщика ставит последний релиз поверх текущего; конфигурация сохраняется.

   Чтобы собрать самостоятельно: `make` (создаёт `dist/necorouter-x86_64` и `dist/necorouter-aarch64`,
   нужен Go 1.24+), затем `sudo sh packaging/install.sh --local`.

3. Проверьте, что служба работает:

       necorouter version
       systemctl status necorouter        # systemd
       rc-service necorouter status       # OpenRC / Alpine

4. Войдите по SSH или на консоли под учётной записью Linux. Встроенная учётная запись — `admin` с паролем
   `admin`. Маршрутизатор предупреждает о пароле по умолчанию при входе; смените его сразу:

       configure terminal
       username admin
       password НОВЫЙ_ПАРОЛЬ
       end

5. Сопоставьте порты с сетевыми картами. Порты `te0`, `te1`, … назначаются физическим интерфейсам через
   `/etc/necorouter/ports.map`. Новые карты добавляются автоматически и сопоставляются по MAC-адресу.

### Удаление

    sudo sh packaging/install.sh --uninstall           # сохранить конфигурации
    sudo sh packaging/install.sh --uninstall --purge   # удалить всё, включая учётные записи маршрутизатора

## Быстрый старт

Пример выводит один интерфейс в локальную сеть, добавляет пользователя и раздаёт в этой сети адреса по DHCP.
Предполагается, что физический интерфейс для порта `te0` задан в `ports.map`.

    hostname router1
    ip domain-name lab.local
    !
    interface lan
     ip address 192.168.10.1/24
    !
    port te0
     service-instance te0/lan
      encapsulation untagged
      connect ip interface lan
    !
    end

Как применить:

1. Войдите и перейдите в привилегированный режим командой `enable`, затем `configure terminal`.
2. Вставьте строки выше или введите их по одной.
3. Проверьте результат командой `show running-config`.
4. Сохраните командой `write`. Без `write` конфигурация пропадёт при перезапуске демона.

Полезное при работе: `?` показывает, что можно ввести дальше, `Tab` дополняет слово, `show running-config`
показывает действующую конфигурацию, `write` её сохраняет, `exit` выходит из текущего режима.

## Режимы и роли

В CLI три режима, как в EcoRouter. Приглашение показывает текущий режим.

| Приглашение | Режим | Вход | Назначение |
|---|---|---|---|
| `necorouter>` | пользовательский | логин | состояние (`show version`, `show interface`, `show log` и другие), `terminal`; `ping` только для admin |
| `necorouter#` | привилегированный | `enable` | команды `show` для роли, `ping`, `traceroute`; для admin ещё `write`, `copy`, `reload`, `configure terminal` |
| `necorouter(config)#` | конфигурация | `configure terminal` | конфигурация, только admin |

Роли:

- `admin` может всё.
- `noc` (аудитор) видит состояние в пользовательском режиме и running-конфигурацию с замаскированными секретами (ключи OSPF, pre-shared ключи IPsec и хеш enable-пароля показываются как `*****`). В привилегированном режиме он видит и остальные команды `show` (пользователи, ARP, NTP, часы, службы, аренды DHCP, route-map), может использовать `ping` и `traceroute`. Он не видит startup-конфигурацию, сохранённые файлы и функции и не может менять конфигурацию.
- `helpdesk` может войти в привилегированный режим и использовать там `ping` и `traceroute`; в пользовательском режиме у него есть `disable` и `help`. Команд `show` у него нет.
- Пользователь без роли не может войти в привилегированный режим.

Файл конфигурации загружается без проверок роли и функций: стартовую конфигурацию читает демон, а другой файл через `copy` может загрузить только admin. Те же команды, набранные пользователем, остаются закрытыми, пока их функция выключена.

Внутри подрежима команда верхнего уровня конфигурации, набранная без отступа (например `ip route` или `ip pool` в `(config-router)#`), выполняется из режима конфигурации, а подрежим покидается, как в файле конфигурации.

Команда, которой роль не может пользоваться, выдаёт `% Invalid input detected`, как и неизвестная команда. Полный список команд по режимам — в справочнике [`docs/index.html`](docs/index.html).

## Возможности

**Адресация и порты**
- Адреса интерфейсов, статические маршруты, DNS-серверы и доменное имя, пулы адресов (`ip pool`).
- Порты и VLAN: `port teN` сопоставляется с сетевой картой, сервис-инстансы `service-instance teN/NAME`
  с `encapsulation untagged` или `dot1q`, GRE-туннели.

**NAT и безопасность**
- Динамический NAT с overload и статический destination NAT с hairpin (`ip nat`).
- Списки доступа (`filter-map ipv4`) и профили безопасности (`security-profile`).

**Маршрутизация**
- OSPF (FRR), route-map, списки префиксов и фильтры политики маршрутизации.
- IPsec с IKEv1 и IKEv2, предварительно разделяемые ключи, GRE поверх IPsec (strongSwan).

**Службы**
- DHCP-сервер (dnsmasq): `dhcp-server N`, пулы, шлюз и DNS для клиентов. Аренды: `show dhcp-server clients`,
  сбрасываются командой `clear dhcp-server clients` (привилегированный режим, только admin).
- NTP-клиент (chrony): `ntp server ADDRESS`; `ntp synchronize` сразу переводит часы к серверам.
- Ограничение полосы: сервис-политики на CAKE (см. [Шейпинг трафика](#шейпинг-трафика-и-bufferbloat)).

**Пользователи и доступ**
- Пользователи с ролями `admin`, `noc`, `helpdesk`; права каждой роли описаны в разделе [Режимы и роли](#режимы-и-роли). Пароли хранятся только в учётных записях Linux, но не в конфигурации.
- Вход — обычный Linux (PAM, OpenSSH). Маршрутизатор создаёт учётные записи по `username NAME`.

**Файлы конфигурации**
- `write` сохраняет startup-config; `write file NAME` сохраняет именованные файлы, `show files config` их показывает.
- `show startup-config` (только admin), `show running-config` (для `noc` с замаскированными секретами), а также история, сравнение и копирование между файлами (`feature config-features`).
- Настройка, требующая функцию, загруженная из файла, остаётся в конфигурации и начинает работать, когда в конфигурации есть строка `feature config-features`.
- Заводские настройки: `copy empty-config startup-config` (применяется после перезагрузки) и `copy empty-config running-config` (заменяет running-config и применяет его сразу; только admin, спрашивает подтверждение).
- Копии автосейва (`autosave interval MIN [keep N]`, `no autosave`): список — `show config history`, удаление по одной через `delete config file NAME`. Команды, удаляющей все копии сразу, нет.

**Журналы и CLI**
- Журнал событий и аудит действий пользователей, независимый от journald и syslog.
- Вставка блока строк конфигурации сразу: каждая строка выполняется по порядку.
- `show banner startup` показывает баннер перед входом (консоль и SSH): состояние и текст. `banner startup` и `no banner startup` его включают и выключают.
- Справка `?`, дополнение по Tab, история команд, Ctrl-L очищает экран, `show ... | include/exclude/begin/grep`. Вывода в файл нет, как и в EcoRouter.
- Длинный вывод `show` открывается на отдельной странице на весь экран; `q` возвращает в консоль. `show log follow` открывает живую страницу, которая прокручивается вместе с новыми сообщениями, пока вы не поднимаетесь вверх или не нажмёте `q` или Ctrl-C.

Функции, которые не входят в стандартный синтаксис, включаются командой `feature NAME`; `show features` показывает их состояние.

## Как это устроено

- `necorouter daemon` — фоновая служба. Она хранит работающую конфигурацию и применяет её к системе.
- `necorouter` (CLI) подключается к демону через локальный Unix-сокет. Каждый вход открывает сессию.
- Каждая функция системы реализована отдельным стандартным демоном или инструментом. Он запускается, только если
  конфигурация его требует, и останавливается, когда функция удалена:

| Функция | Компонент |
|---|---|
| Вход и SSH | учётные записи Linux (PAM), OpenSSH |
| NAT, filter-map, профили безопасности | nftables |
| Ограничение полосы | `tc`, qdisc CAKE и IFB через сервис-политики |
| DHCP и DNS | dnsmasq |
| OSPF | FRR (zebra, ospfd) |
| NTP | chrony |
| IPsec | strongSwan (charon, swanctl) |
| Ping и traceroute | iputils, traceroute |

## Шейпинг трафика и bufferbloat

Когда канал загружен полностью, очереди увеличивают задержку ping. Настройте сервис-политики на WAN-сервис-инстансе.
Начните с ограничений примерно 90–95% от измеренной устойчивой скорости, чтобы CAKE держал очередь узкого места
на маршрутизаторе. Политика `in` ограничивает загрузку через IFB, `out` — отдачу на WAN-выходе.
Нужна поддержка CAKE в ядре Linux (`sch_cake`).

Для канала 100/10 Мбит/с начните примерно с 95/9 Мбит/с:

    configure terminal
    service-policy WAN-DOWN
     bandwidth mbps 95
    exit
    service-policy WAN-UP
     bandwidth mbps 9
    exit
    port te0
     service-instance wan
      encapsulation untagged
      connect ip interface wan
      service-policy WAN-DOWN in
      service-policy WAN-UP out
    end
    write
    show service-policy

Используйте свои имена порта и сервис-инстанса. Скорости задаются явно: маршрутизатор не определяет
устойчивую скорость канала провайдера.

## Обновление

В привилегированном режиме:

    update check            текущая версия, последний стабильный релиз и последняя предварительная версия
    update list [N]         N последних релизов (по умолчанию 10)
    update                  установить последний релиз выбранного канала
    update pre              установить новейшую предварительную версию
    update to TAG           установить указанный релиз
    update channel          показать выбранный канал обновлений
    update channel release  использовать стабильные релизы
    update channel pre      использовать предварительные версии для `update` и автопроверки
    update autocheck        проверять при входе и предлагать обновления
    no update autocheck     отключить автоматическую проверку

Обновление идёт в фоне; маршрутизатор перезапускается, сессии завершаются. Ход обновления записывается в
`/var/log/necorouter/update.log`. Релизы проверяются по `SHA256SUMS`; контрольные суммы берутся из того же релиза,
поэтому они защищают от повреждения при загрузке, но не от подменённого релиза. Эти команды обновляют только
necorouter, но не операционную систему.

## Ограничения

- Статический IPsec (ключи `manual`, `show crypto sa`) не реализован; реализован только IPsec на основе IKE.
- BGP не реализован. Route-map поддерживают перераспределение OSPF, но не атрибуты BGP.
- Удалённый syslog и `aaa` с TACACS+ или RADIUS не реализованы.
- Некоторые команды повторяют дизайн коммерческих маршрутизаторов, а не официальную спецификацию. Перед тем как
  полагаться на необычную команду, проверьте её поведение.
- Работа OSPF на FRR, DHCP, NAT и GRE на реальном оборудовании и на каждом поддерживаемом дистрибутиве не проверена.

## Сборка и тесты

    make                # статические бинарники для amd64 и arm64
    make host           # бинарник для этой машины
    make docs           # обновить дерево команд в docs/index.html по коду
    make test           # go vet, модульные тесты и сквозные скрипты

`make test` требует root и `unshare`: сквозные скрипты создают сетевые пространства имён и виртуальные интерфейсы.

После добавления или изменения команды выполните `make docs`: страница документации содержит дерево команд, и `make test` падает, пока она устарела.
Только модульные тесты: `go test ./...`. Добавление команды: опишите узел в файле её режима (`internal/cli/tree_exec.go` для пользовательского и привилегированного режимов, `tree_config.go` для глобальной конфигурации, по файлу на объект, например `tree_iface.go`) и добавьте его в список этого режима. Кто может пользоваться командой, указывается на самом узле: `.For(режим, роли...)`; команда, зависящая от функции, получает ещё `.When(featOn(...))`. После этого выполните `make docs`. Тесты проверяют, что команда доступна из каждого режима конфигурации, что режимы и роли в `For` существуют, что обработчик согласован с тем, что предлагает узел, и что документация актуальна.

## Версии

Версии имеют вид `0.NN` для релизов с новыми функциями и `0.NN.P` для небольших изменений и исправлений поверх `0.NN`
(например, `0.22`, затем `0.22.1`). Релиз с функциями увеличивает `NN` на единицу; исправление увеличивает `P`.
Предварительные версии помечаются как `0.NN-beta.N`. Первый публичный релиз — `0.21`.
