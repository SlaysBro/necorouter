A software router with an industrial-router-style CLI. A single static binary, no dependencies on the router side beyond standard Linux daemons.

Overview

necorouter turns a Linux machine into a router that is managed with commands in a familiar syntax. The configuration is written in the CLI, saved to a file and applied to the system: addresses, routes, NAT, DHCP, NTP, OSPF, VLANs, GRE tunnels and IPsec.

Daemon

necorouter daemon holds the configuration. While it is not running, the router does not work and uses no resources.

Thin client

The login shell necorouter shell connects to the daemon over a socket and passes commands on. The daemon decides the rights by uid.

Lazy services

dnsmasq (DHCP), FRR (OSPF), chrony (NTP) and nftables (NAT) start only when the configuration contains the matching setting, and stop when it is removed.

Command flow

A command is parsed against the mode's tree, checked, applied to the in-memory configuration, and the services are brought into line. If nothing changed, nothing is restarted. write saves the configuration to startup-config, which is replayed at the next start.

  • Services (FRR, dnsmasq, chrony, nftables) start only when the configuration needs them.
  • Users: 1–5 accounts put no load on the system; dozens cause no noticeable load; hundreds work, but applying the configuration reads /etc/passwd for every user.
  • The daemon accepts up to 64 simultaneous sessions.

Installation

Root rights are required. By default the installer downloads the latest stable GitHub release, checks it against SHA256SUMS, installs the dependencies itself where possible, and enables the service. It installs the required packages but does not upgrade the whole operating system.

git clone https://github.com/SlaysBro/necorouter.git
cd necorouter
sudo sh packaging/install.sh                       # latest stable release
sudo sh packaging/install.sh --bin dist/necorouter-x86_64
sudo sh packaging/install.sh --build               # build from sources (Go 1.24+)
sudo sh packaging/install.sh --uninstall           # removes the router, keeps configurations
sudo sh packaging/install.sh --uninstall --purge   # removes everything, including accounts

What the installer does:

  • Downloads with curl, wget, BusyBox wget or Python 3. The checksum file comes from the same release: it detects transfer damage but is not a separate signature.
  • Selects a binary from --bin, --local, or the default release download. Builds from source only with --build.
  • Detects the distribution and the init system (systemd or OpenRC) and installs the service.
  • Creates the links /usr/local/bin/necorouter, /usr/bin/necorouter (for sudo's secure_path) and necorouter-shell.
  • Registers the shell in /etc/shells and adds a restriction block to sshd_config: accounts of the necorouter group get no port, agent or X11 forwarding.
  • Creates the banner /etc/necorouter/banner and writes it to /etc/issue for the console. On Alpine it generates the sshd host keys and enables sshd at boot.

Installer options are described in the README: --version, --pre, --build, --local, --bin, --no-enable, --no-deps.

Login and roles

Login is handled by plain Linux: login on the console and sshd over ssh. The password is checked by PAM. Rights inside the CLI come from the role in the daemon's configuration.

RoleRights
adminFull access: user and privileged modes, configuration. The built-in admin account is created on the first start (password admin, change it with passwd admin).
nocUser mode: show of the status (version, hostname, port, interface, ip, filter-map, security-profile, banner, dhcp-profile) and of the running configuration with the secrets hidden as *****, ping, terminal. Privileged mode (enable): also show of users, route-map, arp, ntp, clock, service-policy, crypto-ipsec, services, DHCP leases, ping, traceroute. No configuration mode and no write, copy, reload.
helpdeskUser mode: enable, exit, logout, terminal, mge, disable, help. Privileged mode: ping, traceroute, terminal, mge, help, exit, logout. No show commands.

A user without a role is considered untrusted: enable is denied. show startup-config, show files, show config and show features are shown only to the admin role. show running-config is shown to noc with the secrets (OSPF keys, IPsec pre-shared keys, the enable password hash) hidden as *****. Commands a role may not use are reported as % Invalid input detected. Deliberate differences from the EcoRouter reference: copy empty-config running-config needs no feature; noc does not see the startup configuration, saved files or features. A configuration file is replayed without the role and feature checks: the startup configuration is read by the daemon, and only admin can load another file with copy. The same commands typed by a user stay closed while their feature is off. A setting that needs a feature, loaded from a file, stays in the configuration and takes effect once feature config-features is in the configuration (for example autosave interval).

Accounts

username NAME in the configuration creates a Linux account with the router's shell and the necorouter group. The password is set with password PASS in the CLI (it changes the Linux account's password) or with passwd NAME in the system. The configuration holds no passwords. Removing username from the configuration deletes the account the router created. Accounts that existed before the router are not deleted; they only get its shell. The router does not touch root and system accounts (uid < 1000).

Pre-login banner

The banner from /etc/necorouter/banner is shown before login: on the console through /etc/issue, over ssh through the Banner directive. The previous /etc/issue is saved and restored on removal. For your own ASCII art, edit /etc/necorouter/banner and run necorouter issue sync. In the CLI, banner startup and no banner startup switch the pre-login banner on and off, and show banner startup shows the state and the text.

Features

Addressing

  • Interface addresses as A.B.C.D/M or A.B.C.D MASK; repeating the command replaces the address.
  • Static routes: ip route PREFIX NEXTHOP.
  • DNS servers and domain name: ip name-server, ip domain-name.
  • Address pools: ip pool NAME RANGE[,RANGE...], each range A.B.C.D[-A.B.C.D].

Ports and VLANs

  • port teN is mapped to a Linux network card (ports.map, detection by MAC).
  • Service instances: service-instance teN/NAME, encapsulation untagged or dot1q VID.
  • Connecting an interface to an instance: connect ip interface NAME inside the instance.
  • GRE tunnels: interface tunnel.N, then ip tunnel SRC DST mode gre.

NAT and security

  • Pool of inside addresses: ip nat pool NAME RANGE[,RANGE...].
  • Dynamic NAT: ip nat source dynamic inside-to-outside pool P overload with an address or interface NAME.
  • Static NAT is in the interface command tree (ip nat ...).
  • Security profiles (security-profile N, security): rules in nftables. The default profile closes SSH, Telnet and SNMP on the router's interfaces.

OSPF routing

  • router ospf ID; network PREFIX area N or network ADDR WILDCARD area N.
  • Authentication on the interface (simple or message-digest).
  • Checking: show ip ospf neighbor, show ip route, show services.
  • The zebra and ospfd daemons (FRR) start only when the configuration contains OSPF.

DHCP

  • dhcp-server N: network, pool, gateway, DNS.
  • dnsmasq starts only if at least one DHCP server is configured.
  • Leases: show dhcp-server clients. To forget all leases: clear dhcp-server clients; clients get new addresses on their next request.

NTP

  • ntp server ADDRESS, ntp timezone utc+3 (or Region/City).
  • chrony starts only when there is an ntp server.
  • ntp synchronize steps the clock to the servers at once. State: show ntp status.

Users and access

  • username NAME; role admin, noc or helpdesk.
  • Passwords live only in Linux accounts (passwd, or password in the CLI). The configuration holds no passwords.
  • Tab offers user names; ? shows only the NAME hint.

Saving and viewing

  • write (or copy running-config startup-config) saves startup-config; write file NAME saves a named file.
  • show running-config, show startup-config, show version, show clock, show hostname, show arp.
  • Paged output: a long show opens in a pager; terminal length N sets lines per page, 0 turns it off.

CLI conveniences

  • ? — hint anywhere; Tab — completion (on an empty line it does nothing); arrows — history.
  • Ctrl-C interrupts ping and traceroute without leaving the CLI.
  • Ctrl-L clears the screen; mge [TEXT] shows an animated steam train with lettering on the tender.
  • Abbreviated commands: sh run, sh ip int br.

Saving

An unsaved configuration lives in the daemon's memory and is already applied to the system. Logging out does not roll it back, and every session sees it. Save it with write; otherwise a daemon restart returns the configuration to startup-config.

  • write or copy running-config startup-config — save the current configuration.
  • show running-config — what is in effect now; show startup-config — what is saved.
  • Crash copy. If the daemon terminated abnormally, at start running-config from the last snapshot is saved to crash-config and startup-config is left unchanged. Read it with show config file crash.
  • Baseline file commands: write file NAME, write terminal, show files config, show config file NAME, copy file NAME startup-config (with a warning).
  • Security profiles: security-profile N → rule 0 permit|deny PROTO SRC DST [eq|gt|lt|range PORT]; security N, no security; show security-profile. Attached profiles cannot be changed: run no security first.
  • Factory defaults: copy empty-config startup-config writes them to startup-config (applied after reload); copy empty-config running-config replaces running-config with them and applies it now; admin only, asks for confirmation. Accounts created on the router are deleted in both cases.
  • Autosave is off by default. Enable it in configuration mode with autosave interval MIN [keep N] (5 minutes and 10 copies by default). A copy is taken only when running-config differs from both startup-config and the newest copy. autosave keep N changes how many copies are kept; the new limit applies when the next copy is written. no autosave stops taking copies and keeps the existing ones. Copies are listed by show config history, read with show config file NAME, compared with show config diff A B, restored with copy file NAME startup-config (or running-config), and removed one at a time with delete config file NAME. There is no command that deletes all copies at once.
  • Extensions are hidden from ? until enabled with feature NAME in configuration mode. config-features covers startup-config history and autosaves, write description, copying between files and into running-config, delete config file, show config diff, and the operations journal (show config journal). no feature NAME turns a function off; settings and files remain.

Advantages

  • Runs on ordinary Linux: no device-specific OS is needed; routing and services are proven daemons (FRR, dnsmasq, chrony, nftables, strongSwan).
  • teN ports are mapped to network cards through ports.map, so interfaces can be assigned to fit a lab setup.
  • Login and passwords are ordinary Linux accounts; there is no separate user database.
  • The commands cover what is needed for practice and exams; anything non-standard is enabled explicitly through feature.
  • The event log and the audit of user actions are kept by the router itself, independent of journald or syslog, and work the same on systemd and OpenRC.

Limitations

What has already been checked automatically and what remains to be checked on the target systems.

  • Real FRR (OSPF) on Alpine and RedOS: the tests use daemon stubs.
  • Real getty/login on a tty and sshd with a Match block on the target systems; useradd/userdel and chpasswd on Alpine (busybox) and CentOS; the RedOS PAM stack.
  • Installing packages from repositories (openssh-server, nftables, dnsmasq, frr, chrony).
  • Kernel features: VLAN, GRE and DHCP on real hardware (the test environment has only virtual interfaces).
  • Static IPsec (manual keys) and BGP are not implemented.
  • The syntax was checked against the user manual and the tests; before the exam, check individual commands against the documentation of your lab setup.

Testing

The full set is run with make test (root and unshare are required). After adding or changing a command, run make docs: this page embeds the command tree and the access table, and make test fails while they are out of date. Adding a command: define its node in the file of its mode (internal/cli/tree_exec.go for the user and privileged modes, tree_config.go for the global configuration, one file per object such as tree_iface.go) and put it in the list of that mode. Say who may use it on the node itself with .For(mode, roles...); a command that depends on a feature also gets .When(featOn(...)). The tests check that the command is reachable from every configuration mode, that the modes and roles in For exist, that the handler agrees with what the node offers, and that this page is up to date. To run the interactive tests from a namespace without a network: unshare -n -u -m python3 test/pty_cli.py.

Программный маршрутизатор с CLI в стиле промышленных маршрутизаторов. Один статический бинарник; помимо стандартных демонов Linux ничего не требуется.

Обзор

necorouter превращает Linux-машину в маршрутизатор, которым управляют командами привычного синтаксиса. Конфигурация пишется в CLI, сохраняется в файл и применяется к системе: адреса, маршруты, NAT, DHCP, NTP, OSPF, VLAN, GRE-туннели и IPsec.

Демон

necorouter daemon хранит конфигурацию. Пока он не запущен, маршрутизатор не работает и не потребляет ресурсов.

Тонкий клиент

Login-оболочка necorouter shell подключается к демону через сокет и передаёт команды. Права определяет демон по uid.

Службы по требованию

dnsmasq (DHCP), FRR (OSPF), chrony (NTP) и nftables (NAT) запускаются, только если конфигурация содержит нужную настройку, и останавливаются при её удалении.

Путь команды

Команда разбирается по дереву режима, проверяется, применяется к конфигурации в памяти, и службы приводятся в соответствие. Если ничего не изменилось, ничего не перезапускается. write сохраняет конфигурацию в startup-config, которая проигрывается при следующем запуске.

  • Службы (FRR, dnsmasq, chrony, nftables) запускаются только тогда, когда конфигурация в них нуждается.

Установка

Нужны права root. По умолчанию установщик скачивает последний стабильный релиз с GitHub, проверяет его по SHA256SUMS, по возможности ставит зависимости сам и включает службу. Он устанавливает нужные пакеты, но не обновляет всю операционную систему.

git clone https://github.com/SlaysBro/necorouter.git
cd necorouter
sudo sh packaging/install.sh                       # latest stable release
sudo sh packaging/install.sh --bin dist/necorouter-x86_64
sudo sh packaging/install.sh --build               # build from sources (Go 1.24+)
sudo sh packaging/install.sh --uninstall           # removes the router, keeps configurations
sudo sh packaging/install.sh --uninstall --purge   # removes everything, including accounts

Что делает установщик:

  • Загружает через curl, wget, BusyBox wget или Python 3. Файл контрольных сумм берётся из того же релиза: он выявляет повреждения при передаче, но это не отдельная подпись.
  • Выбирает бинарник из --bin, --local или из загрузки релиза. Собирает из исходников только с --build.
  • Определяет дистрибутив и систему инициализации (systemd или OpenRC) и устанавливает службу.
  • Создаёт ссылки /usr/local/bin/necorouter, /usr/bin/necorouter (для secure_path у sudo) и necorouter-shell.
  • Регистрирует оболочку в /etc/shells и добавляет в sshd_config блок ограничений: учётные записи группы necorouter не получают проброс портов, агента и X11.
  • Создаёт баннер /etc/necorouter/banner и записывает его в /etc/issue для консоли. На Alpine генерирует ключи хоста sshd и включает sshd при загрузке.

Параметры установщика описаны в README: --version, --pre, --build, --local, --bin, --no-enable, --no-deps.

Вход и роли

Вход обеспечивает обычный Linux: login на консоли и sshd по ssh. Пароль проверяет PAM. Права внутри CLI определяются ролью в конфигурации демона.

РольПрава
adminПолный доступ: пользовательский и привилегированный режимы, конфигурация. Встроенная учётная запись admin создаётся при первом запуске (пароль admin, сменить: passwd admin).
nocПользовательский режим: show состояния (version, hostname, port, interface, ip, filter-map, security-profile, banner, dhcp-profile) и running-конфигурации с секретами, скрытыми как *****, ping, terminal. Привилегированный режим (enable): ещё show пользователей, route-map, arp, ntp, clock, service-policy, crypto-ipsec, services, аренды DHCP, ping, traceroute. Режима конфигурации и команд write, copy, reload нет.
helpdeskПользовательский режим: enable, exit, logout, terminal, mge, disable, help. Привилегированный режим: ping, traceroute, terminal, mge, help, exit, logout. Команд show нет.

Пользователь без роли считается недоверенным: enable запрещён. show startup-config, show files, show config и show features показываются только роли admin. show running-config показывается роли noc с секретами (ключи OSPF, pre-shared ключи IPsec, хеш enable-пароля), скрытыми как *****. Команды, которые роли недоступны, выдают % Invalid input detected. Намеренные отличия от справочника EcoRouter: copy empty-config running-config не требует функции; noc не видит startup-конфигурацию, сохранённые файлы и функции. Файл конфигурации загружается без проверок роли и функций: стартовую конфигурацию читает демон, а другой файл через copy может загрузить только admin. Те же команды, набранные пользователем, остаются закрытыми, пока их функция выключена. Настройка, требующая функцию, из файла остаётся в конфигурации и начинает работать, когда в конфигурации есть feature config-features (например, autosave interval).

Учётные записи

username NAME в конфигурации создаёт учётную запись Linux с оболочкой маршрутизатора и группой necorouter. Пароль задаётся командой password PASS в CLI (меняется пароль учётной записи Linux) или passwd NAME в системе. В конфигурации паролей нет. Удаление username из конфигурации удаляет учётную запись, созданную маршрутизатором. Учётные записи, существовавшие до маршрутизатора, не удаляются, им только добавляется его оболочка. Root и системные учётные записи (uid < 1000) не затрагиваются.

Баннер перед входом

Баннер из /etc/necorouter/banner виден до входа: на консоли через /etc/issue, по ssh через директиву Banner. Прежний /etc/issue сохраняется и восстанавливается при удалении. Свой ASCII-арт: отредактируйте /etc/necorouter/banner и выполните necorouter issue sync. В CLI banner startup и no banner startup включают и выключают баннер перед входом, а show banner startup показывает состояние и текст.

Возможности

Адресация

  • Адреса интерфейсов в виде A.B.C.D/M или A.B.C.D MASK; повторная команда заменяет адрес.
  • Статические маршруты: ip route PREFIX NEXTHOP.
  • DNS-серверы и доменное имя: ip name-server, ip domain-name.
  • Пулы адресов: ip pool NAME RANGE[,RANGE...], каждый диапазон A.B.C.D[-A.B.C.D].

Порты и VLAN

  • port teN сопоставляется с сетевой картой Linux (ports.map, определение по MAC).
  • Сервис-инстансы: service-instance teN/NAME, инкапсуляция untagged или dot1q VID.
  • Подключение интерфейса к инстансу: connect ip interface NAME внутри инстанса.
  • GRE-туннели: interface tunnel.N, затем ip tunnel SRC DST mode gre.

NAT и безопасность

  • Пул внутренних адресов: ip nat pool NAME RANGE[,RANGE...].
  • Динамический NAT: ip nat source dynamic inside-to-outside pool P overload с адресом или interface NAME.
  • Статический NAT — в дереве команд интерфейса (ip nat ...).
  • Профили безопасности (security-profile N, security): правила в nftables. Профиль default закрывает SSH, Telnet и SNMP на интерфейсах маршрутизатора.

Маршрутизация OSPF

  • router ospf ID; network PREFIX area N или network ADDR WILDCARD area N.
  • Аутентификация на интерфейсе (простая или message-digest).
  • Проверка: show ip ospf neighbor, show ip route, show services.
  • Демоны zebra и ospfd (FRR) запускаются только при наличии OSPF в конфигурации.

DHCP

  • dhcp-server N: сеть, пул, шлюз, DNS.
  • dnsmasq запускается, только если настроен хотя бы один DHCP-сервер.
  • Аренды: show dhcp-server clients. Чтобы забыть все аренды: clear dhcp-server clients; клиенты получат новые адреса при следующем запросе.

NTP

  • ntp server ADDRESS, ntp timezone utc+3 (или Регион/Город).
  • chrony запускается только при наличии ntp server.
  • ntp synchronize сразу переводит часы к серверам. Состояние: show ntp status.

Пользователи и доступ

  • username NAME; роль admin, noc или helpdesk.
  • Пароли — только в учётных записях Linux (passwd или password в CLI). В конфигурации паролей нет.
  • Tab предлагает имена пользователей; ? показывает только подсказку NAME.

Сохранение и просмотр

  • write (или copy running-config startup-config) сохраняет startup-config; write file NAME сохраняет именованный файл.
  • show running-config, show startup-config, show version, show clock, show hostname, show arp.
  • Постраничный вывод: длинный show открывается в пейджере; terminal length N задаёт строки на страницу, 0 — выключает.

Удобство CLI

  • ? — подсказка в любой точке; Tab — дополнение (на пустой строке ничего не делает); стрелки — история.
  • Ctrl-C прерывает ping и traceroute, не выходя из CLI.
  • Ctrl-L очищает экран; mge [TEXT] — анимированный паровозик с надписью на тендере.
  • Сокращения команд: sh run, sh ip int br.

Справочник команд

Дерево построено из той же таблицы команд, что и сам CLI, поэтому совпадает с тем, что показывает ?. Выберите режим, раскройте ветки или воспользуйтесь поиском. Описания команд берутся из программы и на английском.

Сохранение

Несохранённая конфигурация живёт в памяти демона и уже применена к системе. Выход из учётной записи её не откатывает, и её видят все сессии. Сохраните командой write; иначе при перезапуске демона конфигурация вернётся к startup-config.

  • write или copy running-config startup-config — сохранить текущую конфигурацию.
  • show running-config — что действует сейчас; show startup-config — что сохранено.
  • Аварийная копия. Если демон завершился аварийно, при старте running-config из последнего снимка сохраняется в crash-config, а startup-config не меняется. Читать: show config file crash.
  • Базовые команды файлов: write file NAME, write terminal, show files config, show config file NAME, copy file NAME startup-config (с предупреждением).
  • Профили безопасности: security-profile N → rule 0 permit|deny PROTO SRC DST [eq|gt|lt|range PORT]; security N, no security; show security-profile. Привязанный профиль нельзя менять: сначала no security.
  • Заводские настройки: copy empty-config startup-config записывает их в startup-config (применяется после перезагрузки); copy empty-config running-config заменяет running-config и применяет их сразу; только admin, спрашивает подтверждение. В обоих случаях учётные записи, созданные на маршрутизаторе, удаляются.
  • Автосейв выключен по умолчанию. Включается в режиме конфигурации командой autosave interval MIN [keep N] (по умолчанию 5 минут и 10 копий). Копия делается, только если running-config отличается и от startup-config, и от последней копии. autosave keep N меняет число хранимых копий; новый предел применяется при записи следующей копии. no autosave прекращает создание копий и оставляет существующие. Копии показывает show config history, читает show config file NAME, сравнивает show config diff A B, восстанавливает copy file NAME startup-config (или running-config), удаляет по одной командой delete config file NAME. Команды, удаляющей все копии сразу, нет.
  • Расширения скрыты от ?, пока не включены командой feature NAME в режиме конфигурации. config-features — история startup-config и автокопии, write description, копирование между файлами и в running-config, delete config file, show config diff и журнал операций (show config journal). no feature NAME отключает функцию; настройки и файлы остаются.

Преимущества

  • Работает на обычном Linux: не нужна отдельная фирменная ОС; маршрутизация и службы — проверенные демоны (FRR, dnsmasq, chrony, nftables, strongSwan).
  • Порты teN сопоставляются сетевым картам через ports.map, поэтому интерфейсы можно назначить под лабораторную схему.
  • Вход и пароли — обычные учётные записи Linux; отдельной базы пользователей нет.
  • Команды покрывают то, что нужно для практики и экзаменов; всё нестандартное включается явно через feature.
  • Журнал событий и аудит действий пользователей ведёт сам маршрутизатор, независимо от journald и syslog, и одинаково работают на systemd и OpenRC.

Ограничения

Что уже проверено автоматически и что остаётся проверить на целевых системах.

  • Настоящий FRR (OSPF) на Alpine и RedOS: тесты используют заглушки демонов.
  • Настоящие getty/login на tty и sshd с блоком Match на целевых системах; useradd/userdel и chpasswd на Alpine (busybox) и CentOS; стек PAM в RedOS.
  • Установка пакетов из репозиториев (openssh-server, nftables, dnsmasq, frr, chrony).
  • Функции ядра: VLAN, GRE и DHCP на реальном оборудовании (в тестовом окружении только виртуальные интерфейсы).
  • Статический IPsec (ключи manual) и BGP не реализованы.
  • Синтаксис проверен по руководству и тестам; перед экзаменом сверяйте отдельные команды с документацией вашей лабораторной установки.

Тестирование

Полный набор запускается командой make test (нужны root и unshare). Добавление команды: опишите узел в файле её режима (internal/cli/tree_exec.go для пользовательского и привилегированного режимов, tree_config.go для глобальной конфигурации, по файлу на объект, например tree_iface.go) и добавьте его в список этого режима. Кто может пользоваться командой, указывается на самом узле через .For(режим, роли...); команда, зависящая от функции, получает ещё .When(featOn(...)). Тесты проверяют, что команда доступна из каждого режима конфигурации, что режимы и роли в For существуют, что обработчик согласован с узлом и что эта страница актуальна. После добавления или изменения команды выполните make docs: эта страница содержит дерево команд, и make test падает, пока страница устарела. Интерактивные тесты в пространстве имён без сети: unshare -n -u -m python3 test/pty_cli.py.
